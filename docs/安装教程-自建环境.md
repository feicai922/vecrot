# 安装教程（自建环境版）

适用于 GitHub 仓库 **vecrot**（代码）加网盘 models 整包（模型）。仓库可放在任意位置；安装脚本不要求固定盘符。本文的 `D:\vecrot` 和 conda 目录均为示例，执行前替换为自己的路径。新源码版的插件目录是 `vecrot_qgis/`，不是旧分发包的 `plugin/`。

照这份文档从头做完大约需要 **40–90 分钟**，其中大部分时间是等 pip 下载和编译。
全程只需复制粘贴命令，不需要理解每一步在做什么，但**遇到报错请先看 §7**。

> 如果你拿到的是**完整包**（10 GB，含 `deployment/envs/*.tar.gz`），
> 不要用这份文档，直接 `python install.py` 即可，见包内的 README-分发说明.md。

## 1. 开箱检查

### 1.1 硬件与系统要求

| 项         | 最低                       | 建议             |
| --------- | ------------------------ | -------------- |
| 操作系统      | Windows 10 x64           | Windows 11 x64 |
| NVIDIA 显卡 | **4 GB 显存**，支持 CUDA 11.8 | 8 GB 以上        |
| 内存        | 16 GB                    | 32 GB          |
| 磁盘可用空间    | **40 GB**                | 60 GB（含作业中间物）  |

**没有 NVIDIA 显卡的机器跑不了。** 插件能打开、能框选，但点「开始提取」会失败。

### 1.2 确认显卡与驱动

打开 PowerShell：

```powershell
nvidia-smi
```

**必须看到**类似输出：

```
+-----------------------------------------------------------------------------+
| NVIDIA-SMI 552.74      Driver Version: 552.74      CUDA Version: 12.4      |
|-------------------------------+----------------------+----------------------+
| GPU  Name        Persistence-M| Bus-Id        Disp.A | Volatile Uncorr. ECC |
|   0  NVIDIA T400 4GB          | 00000000:01:00.0  On  |                  N/A |
+-------------------------------+----------------------+----------------------+
```

记下两件事：

* **CUDA Version 必须 ≥ 11.8**（我们装的是 cu118 轮子，向下兼容）
* **显存大小**：4 GB 够用，但要在最后调小批大小（见 §8.3）

如果 `nvidia-smi` 报「不是内部或外部命令」→ 显卡驱动没装，去 NVIDIA 官网装最新驱动。

### 1.3 解压到短路径

建议选择较短的路径，盘符和父目录均可自行选择，例如：

```
D:\vecrot\          ✅ 推荐
C:\Users\你的名字\Projects\vecrot\   同样可以，注意总路径长度
```

原因：conda 环境里有些文件的路径接近 Windows 260 字符上限。

解压后应该有这些：

```
D:\vecrot\
├── install.py
├── README.md
├── vecrot_qgis\
├── backend\
├── vecrot\
├── work\
└── deployment\
```

### 1.4 开启 Windows 长路径支持（强烈建议）

以**管理员**身份打开 PowerShell，执行：

```powershell
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
    -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
```

执行完**重启电脑**生效。

### 1.5 确认 conda 可用

```powershell
conda --version
```

没有输出或报错 → 先装 Miniconda：<https://docs.conda.io/en/latest/miniconda.html>
（选 Windows 64-bit，安装时勾选 "Add to PATH"）

## 3. 建第一个环境：GIS（协调器）

这个环境只负责读影像、算坐标、写 GeoPackage，**不装 torch**。

### 3.1 创建环境

打开 **Anaconda Prompt（Miniconda Prompt）**，执行：

```powershell
conda create -n vecrot-geo python=3.11 -y
conda activate vecrot-geo
```

### 3.2 装依赖

```powershell
conda install -c conda-forge rasterio pyproj shapely pyogrio geopandas numpy -y
pip install "opencv-python-headless<5" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

这一步会下载约 300 MB。装完验证：

```powershell
python -c "import rasterio, pyproj, shapely, pyogrio, numpy, cv2; print('GIS 环境 OK', 'cv2', cv2.__version__)"
```

**预期输出**：`GIS 环境 OK cv2 4.x.x`

> **为什么要装 opencv（headless）**
>
> 协调器要把每个检测框按角度**转正裁剪**成小块再送轮廓模型。这一步是
> `cv2.warpAffine`，缺 cv2 时作业会一路跑到 VECTORIZING 阶段才崩：
> `ModuleNotFoundError: No module named 'cv2'` —— 前面几个阶段都成功，
> 很容易误判成模型问题。
>
> 装 `opencv-python-headless` 而不是 `opencv-python`：前者不含 GUI 依赖
> （不需要 Qt/GTK），在服务端和笔记本上都更省事，功能对裁剪完全够用。
> 版本取 `<5` 是为了和 numpy 保持兼容。
>
> 后端也带了纯 numpy 的回退实现（`backend/geo/crop.py:_warp_affine_numpy`），
> 所以缺 cv2 时不会直接崩，但**装了 cv2 才是主路径**，结果与训练时完全一致。

### 3.3 记下这个环境的 python 路径

```powershell
where.exe python
```

第一行就是，例如：

```
D:\Program Files\miniconda\envs\vecrot-geo\python.exe
```

**把这个路径抄下来**，§6 要用。

## 4. 建第二个环境：检测

这个环境跑 Strip-R-CNN / MMRotate，**必须 Python 3.9**。

> 为什么必须 3.9：原训练环境是 3.9（权重目录里的 `.pyc` 标签是 `cpython-39`），
> 且 mmdet 2.x 的 Windows 预编译轮子在该版本最稳。

### 4.1 创建环境

```powershell
conda create -n vecrot-det python=3.9 -y
conda activate vecrot-det
```

### 4.2 装 PyTorch（CUDA 11.8）

```powershell
pip install torch==2.0.1 torchvision==0.15.2 --index-url https://download.pytorch.org/whl/cu118
```

约 2.5 GB，慢的话耐心等。

**验证 CUDA 能用**：

```powershell
python -c "import torch; print('torch', torch.__version__); print('cuda', torch.cuda.is_available()); print('gpu', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A')"
```

**预期**：

```
torch 2.0.1+cu118
cuda True
gpu NVIDIA T400 4GB          ← 你的显卡型号
```

**如果 `cuda False`** → 见 §7.4。

### 4.3 固定 numpy 与 opencv

这两个版本必须卡死，原因见 §7.6：

```powershell
pip install "numpy==1.23.5" "opencv-python==4.8.1.78" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 4.4 装 mmcv-full

```powershell
pip install mmcv-full==1.7.2 -f https://download.openmmlab.com/mmcv/dist/cu118/torch2.0/index.html -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> `-f` 后面那个地址是**预编译轮子源**，必须和你的 torch 版本严格对应。
> 我们的 torch 是 2.0.1，所以用 `torch2.0`。

**验证旋转算子**（这是本项目的核心依赖，必须通过）：

```powershell
python -c "from mmcv.ops import nms_rotated, box_iou_rotated, roi_align_rotated; print('mmcv 旋转算子 OK')"
```

**预期**：`mmcv 旋转算子 OK`

如果报 `ModuleNotFoundError: No module named 'mmcv'` → 见 §7.5。

### 4.5 装 mmdet 与骨干依赖

```powershell
pip install mmdet==2.28.2 "timm==0.9.16" e2cnn "setuptools<81" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

三个都是必需的：

* `mmdet==2.28.2` —— 检测框架主体
* `timm==0.9.16` —— StripNet 骨干用它的 `DropPath` / `trunc_normal_`
* `e2cnn` —— ReResNet 的旋转等变卷积依赖
* `setuptools` —— mmcv 的老代码依赖 `pkg_resources`

### 4.6 装 mmrotate

**注意**：这里要装你解压包里的那份源码，路径按你的实际位置改。

```powershell
cd D:\vecrot\vecrot\models\detector_strip_s\Strip-R-CNN
pip install . --no-deps
```

> 用 `pip install .` **不要**用 `pip install -e .`。
> 后者是可编辑安装，路径会写死在本机，分发给别人时 conda-pack 会拒绝打包。
> 我们这里虽然不分发，但保持一致更省事。

**验证**：

```powershell
cd D:\vecrot
python -c "from mmrotate.models.detectors import StripRCNN; from mmrotate.models.backbones import StripNet; print('StripRCNN / StripNet OK')"
```

**预期**：`StripRCNN / StripNet OK`

> 不要用 `import mmrotate` 验证：这个分支的 `datasets/__init__.py` 导入了
> `dota.py` 里不存在的类，顶层 import 必定失败（上游 bug，见 §7.7）。
> 我们的后端用 `sys.modules` 桩绕过，正常使用不受影响。

### 4.7 记下这个环境的 python 路径

```powershell
where.exe python
```

例如：`D:\Program Files\miniconda\envs\vecrot-det\python.exe`

## 5. 建第三个环境：轮廓

这个环境跑 VectorLLM（Qwen3 多模态），**必须 Python 3.11**。

### 5.1 创建环境

```powershell
conda create -n vecrot-vllm python=3.11 -y
conda activate vecrot-vllm
```

### 5.2 装 PyTorch（注意版本不同！）

```powershell
pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu118
```

> **为什么这里用 2.4.1 而不是 2.0.1**：
> Qwen3 建模需要 `torch.compiler`（2.1+ 才有）。而且 2.4 带 bf16 的软件补偿路径，
> T400 这类没有 bf16 硬件的卡才能跑 VectorLLM。
> 两个环境 torch 版本不同，是**故意的**，不是配错。

### 5.3 装其余依赖

```powershell
pip install "transformers==4.57.1" timm safetensors einops "numpy<2" "opencv-python==4.11.0.86" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

**版本必须对齐**：

| 包              | 版本         | 为什么                                                         |
| -------------- | ---------- | ----------------------------------------------------------- |
| `transformers` | **4.57.1** | 4.51 缺 `MultiModalData`；4.56+ 需要 torch≥2.2；5.x 需要 torch≥2.6 |
| `numpy`        | **<2**     | transformers 4.57 与 numpy 2 有兼容问题                           |
| `timm`         | 最新即可       | VectorLLM 视觉塔用                                              |
| `einops`       | 最新即可       | 模型内部张量重排用                                                   |

### 5.4 验证

```powershell
python -c "import torch, transformers; print('torch', torch.__version__); print('transformers', transformers.__version__); from transformers import Qwen3ForCausalLM, RTDetrForObjectDetection; print('Qwen3 + RTDetr API OK')"
```

**预期**：

```
torch 2.4.1+cu118
transformers 4.57.1
Qwen3 + RTDetr API OK
```

### 5.5 记下这个环境的 python 路径

```powershell
where.exe python
```

例如：`D:\Program Files\miniconda\envs\vecrot-vllm\python.exe`

## 6. 配置并安装插件

### 6.1 打开要编辑的文件

用记事本或 VSCode 打开：

```
D:\vecrot\deployment\manifest.template.json
```

### 6.2 填入三个 python 路径

找到 `"environments"` 这一段，把 `"python": ""` 换成你记下的真实路径：

```json
"environments": {
  "coordinator": {
    "python": "D:\\Program Files\\miniconda\\envs\\vecrot-geo\\python.exe"
  },
  "detector": {
    "python": "D:\\Program Files\\miniconda\\envs\\vecrot-det\\python.exe"
  },
  "vector": {
    "python": "D:\\Program Files\\miniconda\\envs\\vecrot-vllm\\python.exe"
  },
  "detector_hf": {
    "python": "D:\\Program Files\\miniconda\\envs\\vecrot-vllm\\python.exe"
  }
}
```

**三个要点**：

1. **必须用双反斜杠 `\\`**（JSON 语法要求，单反斜杠会报解析错误）
2. `detector_hf` 指向 **`vecrot-vllm`**（RT-DETR 复用 transformers 环境）
3. 路径里有空格没关系（`Program Files` 是合法的）

改完后**另存为** `manifest.json`（同一个 `deployment\` 目录）：

```
D:\vecrot\deployment\manifest.json
```

> 保留 `manifest.template.json` 不动，它是模板。

### 6.3 设置协调器环境变量

因为模板里 `coordinator` 的路径要手动填，我做了个更省事的办法 —— 用环境变量：

```powershell
setx VECROT_PY_COORDINATOR "D:\Program Files\miniconda\envs\vecrot-geo\python.exe"
```

设置后**新开的** PowerShell 窗口才生效。

### 6.4 运行安装脚本

```powershell
cd D:\vecrot
python install.py
```

GitHub 源码版要求先自行建立环境；安装器不负责解包环境。

**预期输出**：

```

       OK QGIS/QGIS3 vecrot/manifest_path = ...

[4/4] 自检
       ✓ coordinator  D:\...\envs\vecrot-geo\python.exe
       ✓ detector     D:\...\envs\vecrot-det\python.exe
       ✓ vector       D:\...\envs\vecrot-vllm\python.exe
```

## 7. 验证与排错

### 7.1 分层自检（出问题先跑这个）

按顺序跑，**哪一层报错就查哪一层**，不用全跑一遍。

```powershell

python install.py --check
```

**预期**（尾部）：

```
       ✓ coordinator  D:\...\envs\vecrot-geo\python.exe
       ✓ detector     D:\...\envs\vecrot-det\python.exe
       ✓ vector       D:\...\envs\vecrot-vllm\python.exe
       ✓ detector_hf  D:\...\envs\vecrot-vllm\python.exe
       ✓ 检测权重: D:\vecrot\vecrot\models\detector_strip_s\best_mAP_iter_90288.pth

```

八行全 `✓` 才能往下走。

#### 第 2 层：协调器能不能干活

```powershell
$GEO = "D:\Program Files\miniconda\envs\vecrot-geo\python.exe"

& $GEO deployment\selfcheck.py --layer paths
& $GEO deployment\selfcheck.py --layer geometry
& $GEO deployment\selfcheck.py --layer geopackage
```

**预期**三行 `全部通过`。验证内容：路径解析、坐标往返精度（≤1e-8 像素）、

### 7.2 常见错误对照表

| 报错                                                 | 原因                    | 解决                         |
| -------------------------------------------------- | --------------------- | -------------------------- |
| `conda : 无法将"conda"项识别为 cmdlet`                    | conda 没加到 PATH        | 用 Anaconda Prompt，或用完整路径调用 |
| `pip: command not found`                           | 环境没激活                 | `conda activate 环境名`       |
| `ModuleNotFoundError: No module named 'mmcv'`      | mmcv 没装上              | 见 §7.5                     |
| `cuda False`                                       | torch 是 CPU 版 或驱动太旧   | 见 §7.4                     |
| `numpy 1.24+ ... module compiled with NumPy 1.x`   | numpy 版本被升级了          | 见 §7.6                     |
| `ImportError: cannot import name 'DOTAv15Dataset'` | mmrotate 这个分支的老问题     | **正常现象**，后端已做兼容，见 §7.7     |
| `transformers ... MultiModalData`                  | transformers 版本太低     | 装 4.57.1，见 §5.3            |
| `torch.compiler 不存在`                               | torch 太旧              | 轮廓环境必须 2.4.1，见 §5.2        |
| `cutlassF: no kernel found`                        | 显卡不支持 bf16 且 torch 太旧 | 轮廓环境必须 2.4.1，见 §7.8        |
| manifest 读不出来                                      | JSON 里有单反斜杠           | 改成 `\\`，见 §6.2             |
| 面板显示所有文件 ✗                                         | 仓库根没定位到               | 重跑 `install.py`，见 §7.9     |

### 7.4 `cuda False` 怎么查

### 7.5 mmcv 装不上的三种情形

**情形 A：pip 报 `Failed to build 'mmcv-full'`（在编译源码）**

说明找不到预编译轮子。检查 `-f` 地址里的 torch 版本和你的实际 torch 是否一致：

```powershell
python -c "import torch; print(torch.__version__)"
# 输出 2.0.1+cu118 → -f 用 torch2.0
# 输出 2.1.x      → -f 用 torch2.1
```

**情形 B：报 `No module named 'pkg_resources'`**

```powershell
pip install "setuptools<81"
```

然后重试 §4.4。

**情形 C：装上了但 `import mmcv` 报 numpy 相关错误**

```powershell
pip install "numpy==1.23.5"
```

### 7.6 为什么 numpy / opencv 版本要卡死

mmcv 1.x 的 C 扩展是用 numpy 1.x 编译的，numpy 2.x 会报
`module compiled with NumPy 1.x cannot be run in NumPy 2.x`。

而 opencv 5.x 要求 numpy ≥ 2，两者冲突。所以检测环境固定：

```
numpy 1.23.5 + opencv 4.8.1.78
```

**不要**在这个环境里升级这两个包。

### 7.7 `DOTAv15Dataset` 报错是正常的

如果你手动 `import mmrotate` 会看到：

```
ImportError: cannot import name 'DOTAv15Dataset' from 'mmrotate.datasets.dota'
```

这是**上游这个分支自身的 bug**：`dota.py` 里只有 `DOTADataset` 一个类，
但 `datasets/__init__.py` 导入了三个。上游精简了文件但忘了改 `__init__.py`。

**不影响使用**。`backend/detector/strip_rcnn_backend.py::import_mmrotate()`
用 `sys.modules` 桩绕过了这个问题，正常从插件跑不会碰到。

### 7.8 `cutlassF: no kernel found`

这个错误说明你的显卡（如 T400、T4、GTX 16xx 等 sm_75 及以下的卡）
硬件没有 bf16 支持，而 torch 版本太旧没有软件补偿路径。

**解决**：轮廓环境必须用 **torch 2.4.1**（§5.2），不要用 2.0.1。

验证：

```powershell
& "D:\Program Files\miniconda\envs\vecrot-vllm\python.exe" -c "import torch; q=torch.randn(1,8,256,64,dtype=torch.bfloat16,device='cuda'); torch.nn.functional.scaled_dot_product_attention(q,q,q); print('bf16 SDPA OK')"
```

输出 `bf16 SDPA OK` 就没问题。

### 7.9 面板显示所有文件 ✗

插件装在 QGIS profile 里，它需要靠 manifest 找到你解压的那个目录。

```powershell
# 检查 QGIS 设置里有没有 manifest 路径
cd D:\vecrot
& "C:\Program Files\QGIS 3.xx\bin\python-qgis-ltr.bat" -c "from qgis.core import QgsSettings; print(QgsSettings().value('vecrot/manifest_path','',type=str))"
```

没输出或路径不对 → 重跑 `python install.py`。

还不够的话，设个环境变量兜底：

```powershell

```

然后重启 QGIS。

## 8. 第一次运行

### 8.1 重启 QGIS 并打开面板

1. **完全退出 QGIS 再打开**（插件 Python 在启动时加载，不重启不生效）
2. 菜单栏 → **`Vecrot`** → **`Vecrot 建筑提取`**
3. 右侧出现面板

**第一次点「开始提取」会有约 30 秒的模型加载**，属正常。

### 8.2 面板操作

```
1. 输入影像   ← 下拉框选当前项目里已加载的栅格图层
                （先把影像拖进 QGIS 就能在这里选到；WMS/WMTS 不会出现）
2. 框选范围   ← 点「在地图上框选」，在画布拖矩形
                框选后矩形保留在图上，点「清除」才消失
3. 输出       ← 选输出目录
4. 开始提取
5. 结果       ← 自动加载到地图
6. 增量提取   ← 再框一块 → 「继续提取新框选」
```

### 8.3 4 GB 显存要调小批大小

面板 → `高级设置` → **生成批大小**，从 **2** 开始试。

如果报 `CUDA out of memory`：

1. 把批大小降到 **1**
2. 还不行就在高层设置里取消勾选「自动加载」后重试

### 8.4 选哪个模型

面板 → `高级设置` → **模型搭配**：

| 组合                                     | 什么时候用                                    |
| -------------------------------------- | ---------------------------------------- |
| **建筑专用 · Strip-R-CNN-S + 场景分类**        | **默认，推荐**。先判窗口有没有建筑，无建筑直接跳过，大范围推理快 3.5 倍 |
| 建筑专用 · Strip-R-CNN-S + ScaleCond 0.55M | 不带场景分类的版本                                |
| 卫星屋顶 · RT-DETR R101vd                  | 想对比另一个检测器时用。它是水平框，小目标较弱                  |
| 只跑轮廓                                   | 已有 jsonl 检测结果，只想跑轮廓                      |

下拉框下面会列出每个文件的就绪状态（✓/✗）。**缺文件时「开始提取」是灰的**。

### 8.5 怎么判断跑成功了

跑完后看两点：

1. 面板日志最后一行是 `✓ 成果：<目录>`
2. 地图上出现两个图层：`检测框`（彩色线框）和 `建筑轮廓`（红色实心多边形）

如果只有检测框没有轮廓，打开成果目录的 `report.json`，看：

```json
"counts": {
  "kept_boxes": 58,
  "buildings_written": 58      ← 这两个数应该相等
}
```

不相等说明轮廓阶段有失败，看 `vectorization` 那一段的 `error` 数。
