下载整个 `models` 文件夹，放到 **仓库根目录下的 `vecrot/`**。压缩包则先解压，避免形成 `vecrot/models/models/`。模型包和代码使用同一发布版本；已有同名文件先备份，再合并对应版本的配置。

```text
<仓库根>/
├─ install.py
├─ third_party/
│  ├─ Strip-R-CNN/                  # GitHub 自带定制检测源码与配置
│  │  └─ configs/gzda/
│  └─ RiO-DETRv2/                   # 可选：只有要跑 RiO-DETR 才需要

      ├─ official_vocab_635/        # 必需：轮廓基座目录
      ├─ detector_strip_s_scene/    # 一个模型文件夹（见下节）
      ├─ detector_strip_s/
      ├─ detector_rt-detr_bbox/
      └─ base_v1/                   # 可选：重建原料，正常推理不用
```

在 PowerShell 7 中检查：

```powershell
python -X utf8 deployment/verify_models.py
python -X utf8 install.py --check
python -X utf8 install.py
```

模型检查核对必需文件、定制模块与最小体积，不加载模型，也不能替代真实推理验证。外部 conda 环境仍需按 [安装教程](安装教程-自建环境.md) 建立。安装、卸载、调试命令见 [插件管理](插件安装卸载与本机调试.md)。

## 模型文件夹约定（重要）

面板上的「模型搭配」下拉框，**每一项就是一个文件夹**：`vecrot/models/<任意名>/`。
文件夹里的 `model.json` 声明自己是哪个后端、用哪份权重、配哪份配置、几类、阈值多少。
所以：

* **加一个模型 = 建一个文件夹**，不用改任何代码；
* 权重和配置在同一个 `model.json` 里成对声明，「换了权重忘了换配置」这种错配不可能再发生；
* 文件夹里任何必需文件缺失，面板会显示 ✗ 并写明缺哪个，不会等到作业跑一半才炸。

### 目录形态

```text
vecrot/models/strip_s_fusion/
├─ model.json                     # 必须
├─ best_mAP_iter_xxxxx.pth        # 权重
└─ strip_s_fusion.py              # 配置（也可以用 src: 指向源码树）
```

### model.json 字段

```json
{
  "spec_version": 1,
  "key": "strip_s_fusion",
  "label": "融合数据集 · Strip-R-CNN-S（旋转框）",
  "backend": "strip_s_gzda",
  "num_classes": 1,
  "repo": "repo:third_party/Strip-R-CNN",
  "weights": "best_mAP_iter_xxxxx.pth",
  "config": "src:configs/gzda/strip_s_gzda.py",
  "detector_options": {"score_thr": 0.05, "nms_iou": 0.3, "max_per_img": 2000},
  "order": 10,
  "note": "融合数据集重训，R/P 见 docs/STATUS.md"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `spec_version` | 否 | 固定 `1`，不匹配会被跳过并说明原因 |
| `key` | 否 | 唯一标识，默认用文件夹名 |
| `label` | 否 | 下拉框显示的文字，默认用文件夹名 |
| `backend` | **是** | `strip_s_gzda` / `mmrotate_obb` / `mmdet_hbb` / `rtdetr_hf` / `rio_detr` / `jsonl` |
| `num_classes` | 否 | 类别数；`strip_s_gzda` 目前恒为 1 |
| `repo` | 否 | 源码树目录（`strip_s_gzda` / `rio_detr` 需要） |
| `weights` | 视后端 | 权重文件；HF 那种「目录即模型」写 `"."` |
| `config` | 视后端 | `.py`（mmcv 系）或 `.yml`（RiO-DETR） |
| `detector_options` | 否 | 后端参数，如 `score_thr` / `nms_iou` / `scene_threshold` |
| `vector` | 否 | `{"ckpt": …, "base": …}`，覆盖默认轮廓权重 |
| `order` | 否 | 下拉排序，越小越前（默认 100） |
| `enabled` | 否 | `false` 时不在面板出现 |
| `note` | 否 | 面板上显示的一句说明 |

### 路径写法

| 写法 | 含义 |
|---|---|
| `best.pth` | 相对**本文件夹** |
| `.` | 本文件夹自身（HF 目录即模型） |
| `src:configs/gzda/x.py` | 相对本模型 `repo` 声明的源码树（**最常用**） |
| `repo:third_party/Strip-R-CNN/configs/x.py` | 相对**仓库根** |
| `models:adaptor_sc_055m` | 相对 **models 根**（共用别的文件夹） |
| `D:\...` / `/abs/...` | 绝对路径 |

### 老模型的迁移

网盘里的 models 包是老约定（没有 `model.json`）。第一次升级代码后执行一次：

```powershell
python -X utf8 deployment\migrate_model_folders.py
```

按已知目录名补写 `model.json`（**只写声明，不动权重**，幂等，手改过的文件不会被覆盖）。
`install.py` 也会自动跑这一步。有模型文件但没写的目录会被列出来，等你补声明。

## 加一个新模型（一条命令）

不用手写 JSON —— 路径前缀（`src:` / `repo:` / `models:`）和必需字段很容易记错：

```powershell
# 融合数据集重训的 Strip-R-CNN-S（结构与原来一致，只是新权重）
python -X utf8 deployment\add_model_folder.py --name strip_s_fusion ^
    --backend strip_s_gzda ^
    --weights "G:\gzda_fusion\best_mAP_iter_12345.pth" ^
    --config third_party\Strip-R-CNN\configs\gzda\strip_s_gzda.py ^
    --label "融合数据集 · Strip-R-CNN-S（旋转框）" ^
    --num-classes 1 --score-thr 0.05 --order 15

# RiO-DETRv2
python -X utf8 deployment\add_model_folder.py --name rio_gzda --backend rio_detr ^
    --weights "G:\rio\last.pth" ^
    --config third_party\RiODETRv2\configs\rio-gzda\riov2_hgnetv2_x_gzda_12e.yml ^
    --label "RiO-DETRv2-X（融合数据）" --score-thr 0.4 --order 30
```

它会：把权重**复制**进 `vecrot/models/<name>/`（`--no-copy` 则写绝对路径）、
把配置写成 `src:configs/gzda/…`（指向源码树，不复制）、写 `model.json`，
最后**回读校验**一遍告诉你缺不缺文件。重启 QGIS 即可在下拉框里选到。

> 若融合训练用了自己新增的配置或数据集注册模块（例如 `custom_imports` 里引用了
> 新文件），把那份 `.py` 一起放进 `third_party/Strip-R-CNN/configs/gzda/`，
> 然后 `--config` 指向它即可（`src:` 会自动算对）。

其它用法：

```powershell
python -X utf8 deployment\add_model_folder.py --list        # 看现有文件夹与就绪状态
python -X utf8 deployment\migrate_model_folders.py          # 老目录补 model.json
python -X utf8 deployment\verify_models.py                  # 全部模型逐项检查
```

### 手写 model.json（参考）

RiO-DETR 的 `.yml` 会 `__include__` 数据集/运行时配置。要么把被 include 的文件一起放进来
（保持相对路径），要么用训练产出里那份已经能跑的 `.yml`（它的 `../dataset/...` 相对源码树，
所以用 `src:` 指过去最省事）。

## 维护者准备模型包

网盘上放**两个**文件夹（内容由脚本生成，不要手抄）：

```powershell
python -X utf8 deployment\build_models_package.py --out "D:\上传" --zip ^
    --rio-config third_party\RiODETRv2\configs\rio-gzda\riov2_hgnetv2_x_gzda_12e.yml
```

| 产物 | 内容 | 给谁 |
|---|---|---|
| `vecrot-models-package.zip` | 完整包骨架：8 个模型文件夹的目录结构 + 每个的 `model.json` + RiO 的单文件配置 + `README-模型包.md` | 新用户整包下载 |
| `vecrot-models-patch.zip`（几 KB） | 只含 5 个文件夹的 `model.json` + 补丁说明 | 已有老模型包的老用户 |

**权重不在脚本里**（几 GB，脚本不碰）。生成骨架后按 `README-模型包.md` 的清单把权重拷进
对应目录，`python deployment\verify_models.py` 全绿后再压缩上传。清单摘要：

| 目录 | 放什么 | 体积 |
|---|---|---|
| `adaptor_sc_055m/` | `trainable.pt` + tokenizer/arch | 未变 |
| `official_vocab_635/` | `model.safetensors` + 3 个 json | 未变，约 1.5 GB |
| `detector_strip_s_scene/` | `best_mAP_iter_37620.pth` | 未变（+ 新增 model.json） |
| `detector_strip_s/` | `best_mAP_iter_90288.pth` | 未变（+ 新增 model.json） |
| `detector_rt-detr_bbox/` | HF 三件套 | 未变（+ 新增 model.json） |
| `detector_strip_s_fusion/` | `best.pth`（融合数据重训） | **新** |
| `detector_rio_gzda/` | `last.pth`（RiO-DETRv2-X） | **新**，配置随包带 |
| `base_v1/` | 可选 | 约 1.7 GB，只影响“重建基座” |

`model.json` 的内容由 `deployment/migrate_model_folders.py::LEGACY` 与
`build_models_package.py::NEW_MODELS` 提供，**与迁移脚本补出来的一致**（有测试守着），
所以"网盘包"和"老目录自动迁移"两条路不会各写一套。

### 源码不进模型包

`third_party/Strip-R-CNN` 与 `third_party/RiO-DETRv2` 随 Git 分发，网盘只放权重。
RiO-DETRv2 的运行还额外需要 conda 环境 `vecrot-rio`（安装教程 §5.6）。
